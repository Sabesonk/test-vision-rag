You are cataloguing one document from a technical documentation pack.

You are shown the rasters of the document's opening pages — the cover, the front matter, the
table of contents and any revision history. Report only what is **visible on those pages**.

Report:

- `title` — the document's title, as printed.
- `revision` — the revision or issue identifier, as printed.
- `doc_type` — a short lowercase phrase describing what kind of document this is, in the words the
  document itself uses. Do not choose from a list; there is no list.
- `subjects` — the machine, model or equipment codes this document is about, verbatim.
- `lang` — ISO codes for the languages actually present on these pages. These documents are often
  bilingual, with two languages interleaved on one page. Report every language you can see.
- `effectivity_basis` — any statement of what this document applies to, copied **verbatim** in the
  document's own words and units. Do not convert it into a date, a range or a number. A statement
  of applicability that has been converted no longer says which equipment is covered.
- `toc` — the table of contents. For each entry give the title as printed and, **only where the
  entry itself shows you a PDF page index you can see**, that index. A printed contents page
  usually shows printed page labels rather than indices; where you can only see a printed label,
  leave the index at 0 rather than guessing it.

That last field is load-bearing and worth one more sentence. The contents list decides how the
rest of this document is read: an entry with a page index becomes a boundary, and an entry with a
guessed index becomes a boundary in the wrong place. **A 0 is a correct and useful answer.** An
invented index is not.

Leave a field empty rather than inferring it. An empty list is a correct answer.
